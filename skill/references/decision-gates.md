# 形态与运行方式判断

先分清两个问题：

1. **产品要单专家还是专家团？** 这决定 Agent、Skill、squad 的产品形态。
2. **技术上怎么跑？** 这决定真实成员派发、确定性内联，还是混合。

不要用第 2 个问题推翻第 1 个问题。

## 一、产品形态

### 单专家

只有产品没有明确要求专家团，且满足以下多数条件时，才考虑单专家：

- 一个领域、一个责任人、一个判断边界。
- 不需要多个专家署名或独立工作台。
- 主流程可以由一个入口 Skill 完成。
- 用户不需要看到成员分工。

生成 `mode=single`：一个 Agent，一个主 Skill，不建 squad。

### 专家团

满足以下任一条件：

- 产品已经定义了多个专家角色或成员卡片。
- 角色之间有明确交接物和不同判断边界。
- 需要独立成员运行、独立 Skill、独立署名或独立产物。
- 团长需要把子任务派给具体成员，并汇总结果。

生成 `mode=team`：团长 + 至少两个成员 Agent + squad 绑定。

> 产品已经定了团，就不要因为“单执行体更快”而偷偷改成单专家。可以在团队内部做性能优化，但不能删除产品角色。

`tools/scaffold.py --mode team` 默认生成真实成员。若产品接受“成员是能力投影”，再在内联方案上单独改造并做 test 会话验证。

## 二、专家团运行方式

### A. 真实成员（默认）

适用：

- 成员有独立 LLM 判断、独立模型、独立工具权限或独立产物。
- 产品需要真实成员卡片、任务时间线和独立执行明细。
- 需要平台原生 squad 协作。

做法：

- 团长 `turn.py` 产生确定性派发计划。
- 用 `deepexi issue create --parent ... --assignee-id ...` 创建 child issue。
- 成员 `run.py` 只处理本角色任务。
- 成员从 child issue 输入 JSON 读取载荷，结果写入 `artifacts/member-result.json`。
- 团长消费成员结果，负责最终回复。

### B. 确定性内联（可选）

适用：

- 产品只需要“专家”作为展示或能力分区。
- 每个角色本质是确定性函数/API，不需要独立 LLM 会话。
- 团队链路必须压到单轮预算内。
- 产品明确接受没有原生成员调度卡、没有独立成员执行明细。

做法：

- 团长在自己的 task 内调用各角色 Skill/Provider。
- 用 `turn.py` 内部状态机串行执行。
- 用投影 child issue 展示阶段卡，但成员 token 为 0。

**不可用条件**：产品要求原生专家调度卡、`/task-runs` 真实成员执行明细、独立成员署名或平台原生 squad 协作时，禁止内联。无 assignee 的投影不会让平台生成成员 Task 卡。

这不叫“把团改成单专家”。这是专家团的一种实现方式，前提是产品接受“成员是投影”。

### C. 混合

适用：

- 重判断角色用真实成员。
- 轻量查询/回写角色用确定性内联。

规则：

- 每个角色明确标注 `runtime: member | inline`。
- 只有 `member` 角色可以创建真实 child issue。
- 只有 `inline` 角色可以在团长沙箱内执行。
- 两种路径都要有幂等和状态恢复测试。

## 三、单专家运行方式

单专家默认：

- 一个 Agent 自己的 task。
- 一个 `turn.py` 主入口。
- 不派发、不建 child issue、不创建 squad。
- 外部系统调用在 Skill/Provider 内完成。

如果单专家出现“多个独立角色”的需求，先回到产品形态重新判断，不要在单专家里偷偷长出一个团。

## 四、运行方式判断表

| 问题 | 选 A 真实成员 | 选 B 内联 |
|---|---|---|
| 成员需要独立 LLM 会话？ | 是 | 否 |
| 成员有独立模型/工具/权限？ | 是 | 通常否 |
| 产品需要原生专家调度卡/成员独立执行明细？ | 是（必须真实成员） | 否（内联不可用） |
| 成员只是 API/规则/图遍历？ | 否 | 是 |
| 单轮预算无法容纳多个成员？ | 需要拓扑/并行 | 优先内联 |
| 产品要求平台原生 squad 协作？ | 是 | 否 |

## 五、什么时候不要建团

- 只有一个判断边界，硬拆成多个角色只会增加冷启动和交接。
- 没有明确交接物，成员之间只能互相“聊天”。
- 团长无法用脚本判断下一个 ready step。
- 团队里没有任何角色需要独立 Agent 能力。

这时候应回到单专家，而不是做一个假团。

## 六、什么时候不要用内联

- 成员需要独立模型、独立权限或独立 runtime。
- 用户/产品明确要求真实成员并行工作。
- 成员需要独立审计、独立报告署名或独立任务明细。
- 平台协议要求团长 delegate，且没有经过 test 环境验证的内联方案。

## 七、性能目标

- 单专家首响：P95 ≤120s。
- 专家团首响：P95 ≤120s。
- 专家团完整链：按产品 SLA，默认 ≤180s。
- 每个 child 的创建、执行、回传都要有 timings 和幂等键。

延迟不达标时，优先优化 payload、冷启动、轮询和派发拓扑，不要先删产品角色。
